# AmongLLM game plugin

Windows BepInEx IL2CPP plugin for Among Us 2026.9.29, built against the interop assemblies generated by the target installation. TOHE and Reactor are optional.

Build with the .NET 10 SDK (the game plugin targets its installed .NET 6 runtime):

```powershell
dotnet build .\AmongLLM.GamePlugin.csproj -c Release -p:LocalAmongUsPath=D:\Game\20260929
```

Install the plugin DLL and **all managed dependency DLLs from the output** in `BepInEx/plugins/AmongLLM/`. These include the Roslyn assemblies used by `execute_csharp`; do not copy game interop or BepInEx core assemblies. Start the MCP server before or after the game: the plugin discovers ports 26767/26768, validates `/healthz`, registers its instance, reconnects with backoff, and sends status every two seconds.

The WebSocket worker does no Unity work. Commands are queued, executed one at a time on the Unity main thread, and correlated with server request IDs. Disconnect, cancellation, and deadlines stop queued work and coroutine steps. Game actions that already completed cannot be undone. Screenshots capture Unity's end-of-frame render; a minimized client that stops rendering can time out.

`get_screen` returns button IDs, hierarchy paths, labels, input IDs, screen dimensions, and a screen ID. `click_button` and `set_text` revalidate that screen. Button selectors accept `buttonId`, `instanceId`, `name`, `path`, exact `label`, `labelContains`, and an optional `scene`; selectors must identify exactly one active button. Hold/repeat buttons need timed input and are excluded from click actions. Sequences support `click`, `wait` with milliseconds, and `waitForButton` with a selector and timeout, resolving each step against current UI.

`send_rpc` uses the actual game's `StartRpcImmediately` and `FinishRpcImmediately`. `send_hazel_message` also accepts raw structured Hazel tokens, where the caller supplies all outer tags and protocol fields. Raw messages use `connection.Send(writer)` and report its synchronous `SendErrors` result. Successful RPC submission does not imply a remote acknowledgement. Writer instances are recycled after use.

`list_net_objects` reads the registered room object collection, including inactive objects, under the native IL2CPP monitor. Room hosts may write any registered object and SnapTo any player. Non-host writes/RPCs are limited to objects they own; reads can inspect all room objects. Read properties with `netObjectId` and optional `members`: omitting members returns available property metadata. Writes use `netObjectId`, `member`, and `value`. Nested struct writes are copied back through containing properties. Direct local property writes do not guarantee network synchronization; use the game's RPC or serialization paths when required.

The account switch checks `Constants.GetPlatformType() == Platforms.StandaloneItch` at runtime, rejects an existing login or connected room, replaces `EOSManager.platformAuthToken`, verifies readback, and calls `LoginWithCorrectPlatform()`. In the installed interop, the original private field is exposed as a public generated property. Its setter uses the native field offset, `ManagedStringToIl2Cpp`, and `FieldWriteWbarrierStub`; there is no patch of a managed getter. Success requires both `HasFinishedLoginFlow()` and `LoginStatus == LoggedIn`. API keys are kept in memory and excluded from the bridge's own status/log messages. `get_account_info(includeUserIdToken:true)` explicitly requests the sensitive EOS token.

`execute_csharp` compiles scripts off-thread and invokes them on the Unity thread. Normal captured awaits resume through Update. Snippets can return values, access game types, and use the `Plugin` global. Execution has the game's full managed privileges. Cancellation is cooperative; synchronous loops and explicit background work cannot be forcibly stopped safely. `list_loaded_mods` enumerates BepInEx's loaded plugin registry, including GUID, name, version, and assembly filename.

Validation distinguishes native metadata inspection, compilation, transport tests, and live game evidence. The automated harness links the actual transport and pure helpers and uses a real HTTP MCP/WebSocket bridge. It does not launch Among Us or validate native game actions.

`read_game_logs` mirrors every BepInEx log source from plugin initialization onward. Each record has a sequence, UTC time, source, level, message, and available stack trace. An `ILogListener` with `LogLevel.All` receives the full stream independently of BepInEx disk-log filters. When no Unity log source is registered, an additive Unity threaded-log callback captures Unity output without replacing existing callbacks. Logs are kept in a 4096-entry cursor buffer and mirrored by a background writer to `%LOCALAPPDATA%/AmongLLM/logs/<instanceId>.jsonl`. Earlier bootstrap output remains in the reported `bootstrapLogPath` (`BepInEx/LogOutput.log`).

Read with `afterSequence:0`, `limit:200`, and optional `sources` / `levels` arrays. Pass the returned `nextSequence` as the next `afterSequence`; it excludes records already returned. Ring-buffer eviction, disk failures, and mirror-queue overflow are reported explicitly. Logs can contain game or other mods' sensitive output; the mirror preserves source content. JSONL capture begins when AmongLLM installs its listener, rather than retroactively claiming to capture earlier startup events.
